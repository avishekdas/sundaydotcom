## 1. How we work

### 1.1 North star & system tests
- The north-star scenario (requirements README) is encoded once in `contracts/north_star.yaml` as **sub-steps**, each tagged with the milestone that delivers it and how it is driven (`api` stub or real `ui`). CI fails if any step is untagged.
- **At milestone kickoff** the milestone's north-star steps are written first and marked `xfail(strict=True)`. The milestone is done when they all pass; a step passing early fails the build (forces tests-first at system level, TP-7).
- **Tier A** — `backend/tests/system/test_north_star.py`: HTTP API through the devserver + InProcessBus + fake clock. Asserts **order and outcome only** (eventual, exactly-once), never wall-clock latency (TP-8). PRs: sync mode + 3 fixed chaos seeds (arch 10 §10.3 aligned); nightly: 500 rotating seeds, failing seeds promoted to the fixed list; seeds printed on failure (TP-12, DL-17).
- **Tier B** — Playwright `e2e/north-star.spec.ts` on deployed dev and staging on every merge to main (real Cognito, Data API, EventBridge, WebSocket, WAF). Latency assertions live here and in k6 as p95 over ≥ 20 runs. Flake policy: 1 retry, quarantine tag with owner + 48 h SLA, flake rate < 1 %, the north-star spec itself can never be quarantined (TP-11).
- **Step 7 (viewer read-only)** is a generated check over the **current route inventory** at every milestone, so it grows automatically (TP-13).

### 1.2 TDD, enforced
- Per story: pick an AC → failing test at the lowest layer that proves it → simplest code → refactor → tag the test `@ac("AC-…")` (pytest marker / Playwright tag).
- **CI evidence of tests-first (TP-6)**: CI runs on **every pushed commit**; red runs are recorded by **test id + branch** (survives squash/force-push). A PR that introduces an `@ac` test must show a recorded red run of that test id on its branch; otherwise the "tests-first" check fails.
- **AC coverage gate (TP-5/6/18)**: generated from the area files: every AC **owned** by the current milestone has ≥ 1 passing tagged test; no tag points to an unknown AC; AC totals in `traceability.md` are regenerated by CI and must match the area files (today 194).
- **Generated tests** stay in sync with their sources: permission matrix (K1/K3 tables), visibility table (arch 07 §7.2a) + a **metamorphic test** (every read path returns a subset of `VisibleItems`), column codec contract (C40.6), QuerySpec golden corpus, formula golden table + **Hypothesis differential test** (Python evaluator vs SQL compiler), automation catalog snapshot (TP-15).
- **Frontend layers (TP-16)**: Vitest + Testing Library for every column cell/editor, filter UI, item page, automation slot widgets; property tests for the reconciler; Playwright for flows. Nightly mutation testing (mutmut/Stryker) on authz, codecs, formula, reconciler with score ≥ 70 %.
- Coverage ≥ 90 % lines on domain packages; mypy --strict; import-linter layers; contract drift checks; **PR CI ≤ 10 min**, tracked per milestone and sharded before exceeding (TP-17).

### 1.3 Milestone done (checklist with evidence links, TP-17)
1. All owned ACs green (CI AC-coverage report link).
2. North-star steps for the milestone flipped from xfail to pass in Tier A and Tier B (run links).
3. Load gate for the milestone met (§4 table, k6 report link).
4. No open Sev1/Sev2; **every queue/worker introduced in the milestone ships with its Sev1/Sev2 alarms, a runbook URL in the alarm, a dashboard panel and its DLQ policy** (CDK assertion, PE-7).
5. Decision log / ADRs updated; traceability diff link.
6. Demo + system test report reviewed by the user — review time-boxed to 2 working days; spikes and test scaffolding for the next milestone may start during the review (DL-20).
7. **Independent milestone review**: a reviewer agent that did not build the milestone checks the evidence above against the plan and the requirements (owned ACs, north-star steps, exit criteria) and files findings in `docs/04-plan/milestone-reviews/<milestone>.md`; blocking findings are fixed before the milestone is marked done (user request, 2026-10-25).
